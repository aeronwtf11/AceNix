## Confirmed fixes

- Service discovery isolates thrown option values and avoids forcing hidden
  compatibility aliases. Regression testing also exposed an obsolete FRP alias
  that calls `abort`, which native `tryEval` cannot catch. Such names remain
  explicitly unavailable instead of being falsely reported disabled.
- Generation listing reads Nix's native links without a profile write lock.
  Running, booted, profile-default and next-boot systems remain distinct.
- Unreadable regular auxiliary files retain metadata in the conflict snapshot
  but are omitted from the candidate with warnings. Actual unreadable imports
  still fail; inaccessible directories still fail; source/ownership protections
  remain enforced.
- Doctor treats missing source write access as a warning. Evaluation failures,
  conflicts, missing tools and interrupted journals remain failures.
- Human output now has command-specific summaries, tables, readable errors,
  explicit staging semantics, real transaction progress and optional file diffs.
  JSON remains complete; quiet mode suppresses progress; verbose diagnostics,
  `NO_COLOR`, terminal detection and ASCII output remain available.
  Interactive confirmation prompts use stderr so JSON stdout stays clean, and
  end-of-input cancels safely instead of exposing a Python traceback.
- Changed sensitive values retain an explicit change flag after redaction, so
  the preview does not accidentally describe them as unchanged. Modern desktop
  managers are included in high-impact checks. Explicit authorization is retained
  for sensitive settings even when sources match: apply can still change runtime
  and the next-boot system.

## GitHub Actions

The original main run [40501820313](https://github.com/aeronwtf11/AceNix/actions/runs/40501820313)
failed during `nix flake check --no-build --all-systems`, after Nix installation
succeeded. All three Nix matrix jobs run this evaluation before their builds.
The installer defaults to Nix 2.35.4. A clean official 2.35.4 container reproduced
the failure: nested `getFlake` tried to open the raw Nixpkgs archive's store path,
which lazy input evaluation had not materialized. A clean 2.28.5 run passed,
explaining why previous local verification missed the CI regression.

The fixture now receives the already resolved Nixpkgs `lib.nixosSystem` function
from the outer flake. It keeps the pinned archive for offline guest rebuilds,
and all four prebuilt flake system derivations remain byte-identical to the old
evaluation for the same application source. Fresh 2.35.4 evaluation passes all
systems without prefetching the archive or disabling checks. Fix commit
`81e2856` was pushed to both source branches; follow-up hosted runs are
[main](https://github.com/aeronwtf11/AceNix/actions/runs/40517770075) and
[release](https://github.com/aeronwtf11/AceNix/actions/runs/40517770570).
The main run's package job, native evaluation step, GRUB check and EFI/flake
check all completed successfully on GitHub. These results verify the CI repair
at `81e2856`; the terminal UX changes are verified separately afterward.

Native CLI regression tests execute the installed `acenix` entry point. The
development shell supplies that executable as well as Python and native tools.
The boot checks additionally inspect generations as `nobody` and, for the
traditional target, preview around a root-only backup without changing native
sources, runtime or the boot profile.

## Limits retained

Read-only previews do not grant write access for activation. Local path flakes
need readable source files for Nix's own source fetch. Unavailable hidden service
aliases should be inspected through their current canonical option. Reboot
advice is an inference from changed boot/hardware/hostname options, not a proof
that every possible native module can activate without rebooting. Source syntax,
package ownership, supported bootloader metadata and ARM build limits are
documented in [IMPLEMENTATION.md](IMPLEMENTATION.md).

No live NixOS configuration was edited or activated. Exactly three optional
`TODO(USER)` exercises remain untouched in `acenix/presentation.py`.
